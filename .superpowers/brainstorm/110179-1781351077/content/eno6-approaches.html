ENO-6: Tre tilgange til prompt-generering og alignment-test

Fælles for alle: Jeg genererer prompts → lokal model eksekverer (uden commit) → jeg reviewer → vi lærer

A

Lightweight — Process-fokuseret

ENO ændringer: Ingen ny kode. Bruger eksisterende prompt_runs tabel til at registrere resultater.

Workflow: Jeg genererer prompt → du sender til lokal Claude Code session → lokal model eksekverer → jeg reviewer diff → du committer hvis OK → vi registrerer i prompt_runs → governance templates forbedres.

Fordel: Starter nu. Ingen udviklingstid. Læring med det samme.

B

Tracker — ENO får alignment-dashboard

ENO ændringer: Ny "Alignment Test" panel i ENO. Viser per-projekt alignment status, genererede prompts, og lokal-model resultater. Ny `alignment_tests` tabel.

Workflow: Som A, men med struktureret tracking i ENO's frontend. Dashboard viser hvilke gaps der er lukket, hvilke der mangler, og success-rate per opgavetype.

Fordel: Systematisk overblik. Data-drevet forbedring af både prompts og governance templates.

C

Hybrid — Start lightweight, byg tracker incrementalt

Fase 1 (nu): Lightweight proces på 2-3 prompts. Lær hvad der virker. Få baseline data.

Fase 2 (efter baseline): Byg alignment-dashboard i ENO baseret på erfaringerne fra fase 1.

Fordel: Vi bygger ikke features før vi ved hvad vi har brug for. Undgår over-engineering.
