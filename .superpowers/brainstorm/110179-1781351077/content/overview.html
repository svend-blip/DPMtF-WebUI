Brainstorm: 2O + ENO-6

To parallelle design-opgaver under DPMtF governance

2O — Parallel-kørsel test (DPMtF-WebUI)

Hvad: Sidste fase i Blok 6. Sammenlign prompt-eksekvering på cloud (deepseek-v4-pro:cloud) vs lokal (qwen36-27b-q4km).

Eksisterende infrastruktur: prompt_templates, prompt_runs, workflow_runs, template_model_hitrates

Mål: Baseline performance-data til model selection decision tree

Metrics: Success, duration, tokens, cost, output quality

ENO-6 — Næste funktionelle fase (ENO)

Hvad: ENO's kerne er complete — evaluation, nightrun, i18n, panel groups. Hvad er næste skridt?

Mulige retninger: Sammenlignings-visualiseringer, historiske trends, integration med DPMtF prompt compiler, auto-re-evaluering

Relation til 2O: Kunne ENO være consumer af 2O's sammenlignings-data?

Første spørgsmål

Skal vi designe disse sammen (2O producerer data som ENO-6 konsumerer) eller hver for sig (uafhængige designs)?

A

Sammen — integreret design

2O bygger sammenlignings-infrastruktur i DPMtF-WebUI. ENO-6 bygger visualisering der consumer 2O's data via API. Ét sammenhængende system.

B

Hver for sig — uafhængige designs

2O designes som DPMtF-WebUI feature. ENO-6 designes som ENO's egen næste fase — kan være noget helt andet end sammenligning.
